# Ввод накладных в מלАי Cash On Tab — плейбук для Claude в браузере

> **Обновление 2026-08-23:** кроме способа ниже (Claude в браузере, вручную)
> теперь есть и полностью автоматический путь — кнопка "🤖 הכנס למלАי
> אוטומטית" на карточке накладной в `inventory.html`, которая дёргает
> `POST /api/inventory/auto-enter/{id}`. Сервер сам логинится в Cash On Tab
> (headless-браузер, см. `cashontab_bot.py`) и создаёт документ без участия
> Кетерины. Требует переменных окружения `CASHONTAB_COMPANY_CODE` /
> `CASHONTAB_USERNAME` / `CASHONTAB_PASSWORD` на Render (см. докстринг
> `cashontab_bot.py`). Это первая версия, написанная по скриншотам, без
> доступа к реальному HTML Cash On Tab — почти наверняка потребует минимум
> один круг отладки на реальном сайте, особенно строка входа (`_login`) и
> заполнение строк товара (`_fill_line_item`). Способ ниже (Claude в
> браузере) остаётся рабочим запасным вариантом на случай, если бот
> застрянет или Cash On Tab обновит интерфейс.

## Зачем это

У Cash On Tab (Autosoft) нет публичного API, и никакого API-токена они не
дают (проверено). Поэтому автоматический ввод накладных с этого сервера
(Render) невозможен в принципе — сервер не может залогиниться в Cash On Tab
сам.

Единственный рабочий путь — тот же, что уже используется для синхронизации
каталога товаров (см. `catalog_store.py`): **Claude в браузере на компьютере
Кетерины**, во время её собственной, уже открытой сессии в Cash On Tab.
Пароль от Cash On Tab при этом никогда никуда не передаётся и не
сохраняется — используется только её живая, уже залогиненная сессия.

## Откуда брать данные

Наш сервер уже читает накладные из почты, распознаёт позиции и сопоставляет
их с товарами каталога (см. `invoice_ingest.py`, `item_matcher.py`). Чтобы
не гадать, что именно вводить, вся нужная информация отдаётся одним
запросом:

```
GET /api/inventory/ready-for-entry
```

(тот же сайт, что и панель `מלАי`/`inventory.html` — если Claude в браузере
открыт в контексте, где Кетерина уже залогинена на этом сайте, обычный
`fetch` с куки сессии сработает).

Возвращает только те накладные, которые **полностью проверены** и ещё не
отмечены как введённые: филиал назначен, у каждой позиции либо есть код
товара Cash On Tab, либо она явно помечена "skip" (не нужно вводить).
Накладная с хотя бы одной неподтверждённой позицией в список не попадёт —
это осознанно, чтобы не рисковать частичным/неверным вводом.

Пример ответа:

```json
[
  {
    "id": 123,
    "branch": "רעננה",
    "supplier_domain": "hadarrosen.com",
    "supplier_name": "הדר רוזן",
    "invoice_number": "12345",
    "received_at": "2026-08-15T09:12:00+00:00",
    "items": [
      {"code": "10234", "name": "שמפו רכב 5 ליטר", "quantity": 4, "unit_price": 32.5}
    ]
  }
]
```

`supplier_name` — это точное имя ספק, под которым поставщик зарегистрирован
в Cash On Tab (`suppliers.py`), чтобы не искать вручную.

## Что нужно сделать (для Claude в браузере, в сессии с Кетериной)

Обрабатывать **по одной накладной за раз** (не пачкой) — так проще заметить
и остановить ошибку, если поиск подобрал не ту строку.

1. Получить список через `GET /api/inventory/ready-for-entry`, взять первую
   накладную из списка.
2. В Cash On Tab: **יצירת מסמך חדש → ת.מ. רכש** (это и есть документ
   поступления товара от поставщика в מלАי — не "קבלה" и не "חשבונית רכש",
   это другие типы документов).
3. Поле **מחסן** — открыть поиск (кнопка `...`), ввести название `branch`,
   выбрать совпадающую строку из результатов. Склад = филиал, у каждого
   свой код, но код хранить не нужно — ищем по имени каждый раз.
4. Поле **קוד ספק** — открыть поиск, ввести `supplier_name`, выбрать
   совпадающую строку.
5. Поле **מספר תעודת ספק** — вписать `invoice_number`.
6. Вкладка **פרטים** (позиции). Для каждой позиции из `items`:
   - нажать **+** (добавить строку)
   - в **קוד פריט** открыть поиск, ввести `code`, выбрать совпадающий товар
     (после выбора Cash On Tab сам подставит название и цену по умолчанию)
   - **важно:** переписать подставленную цену на `unit_price` из
     накладной — цена по умолчанию в карточке товара может отличаться от
     той, что реально была в этой накладной у этого поставщика
   - вписать **כמות** = `quantity`
7. Нажать **צור מסמך** (сохранить документ).
8. После успешного сохранения в Cash On Tab — отметить накладную как
   выполненную и на нашей стороне:
   ```
   POST /api/inventory/mark/{id}
   {"status": "ok"}
   ```
   (тот же запрос, что шлёт кнопка "✓ בוצע" в `inventory.html`).
9. Повторить со следующей накладной из списка.

## На что обратить внимание

- **Названия могут не совпадать буква в букву.** У нас в `branches.py` /
  `suppliers.py` названия филиалов и поставщиков могли записаться чуть
  иначе, чем в Cash On Tab (например, у нас "מודיעין לינד", а в Cash On Tab
  видели "מודיעין ליגד" при первой сверке). Поиск обычно всё равно находит
  нужную строку — просто визуально проверяйте, что выбрали то, что нужно,
  а не первую попавшуюся.
- Если поиск по `branch`/`supplier_name`/`code` не находит совпадений —
  не гадать и не выбирать наугад: остановиться и спросить Кетерину, а не
  продолжать с этой позицией/накладной.
- В Cash On Tab нет импорта из файла для этого типа документа (проверено
  23.08.2026) — только ручной ввод полей, поэтому этот процесс всегда
  требует живой браузерной сессии, а не может быть переведён на сервер.
